Project Abstract

Phishing remains the predominant attack vector in cybercrime, accounting for catastrophic financial losses and credential compromises globally. Traditional detection systems depend heavily on static blacklists (such as Google Safe Browsing or PhishTank), which suffer from significant temporal latency—failing to defend against newly minted zero-hour phishing domains that survive for less than 4 hours.

PhishGuard AI introduces a defensive, non-intrusive machine learning framework that evaluates website URLs strictly at the lexical, structural, and syntactic level. By combining 16 engineered quantitative features with character-level TF-IDF n-grams (3 to 5 grams), the system performs local classification into Safe, Suspicious, or High Risk, generates calibrated 0-100 threat scores, delivers explainable heuristic rationales, and compiles publication-quality PDF audit reports.

Problem Statement

Existing web-based phishing detection utilities present two severe operational handicaps:

  • Active Socket Infiltration Risk: Many commercial crawlers actually visit or fetch DOM elements from submitted URLs. This dangerous practice can execute client-side drive-by malware payloads, alert attackers via DNS telemetry, and violate organizational data sovereignty.
  • Blacklist Latency Gap: Static domain reputation feeds require human or crawler verification, leaving a multi-hour window during which victims interact with newly registered malicious links before blacklisting occurs.

There is an urgent requirement for a high-accuracy, offline-safe machine learning platform capable of instantaneous pre-execution URL triage without initiating socket requests to user-submitted web addresses.

Flask RESTful Server

Scikit-Learn Ensemble

StandardScaler + TfidfVectorizer (char n-grams) stacked into Random Forest classifier.

LAYER 4: PERSISTENCE
SQLite Database Engine

Indexed audit tables storing scan UUIDs, timestamped risk vectors, and JSON finding payloads.

Data Ingestion Pipeline: Raw URL → Normalization (urllib.parse) → Feature Extraction (16 Quantitative Dimensions) + TF-IDF (800 Character 3-to-5 grams) → Sparse Feature Stacking (scipy.sparse.hstack) → Calibrated Random Forest Probability → Heuristic Blending → SQLite Logging → JSON / PDF Response
Mathematical Formulation
1. Character-Level TF-IDF

Term Frequency-Inverse Document Frequency calculates the informational significance of character n-gram tokens $t$ within URL string $d$:

TF-IDF(t, d, D) = TF(t, d) × ln((1 + |D|) / (1 + DF(t))) + 1

Project Limitations & Future Scope

Current Limitations
  • No Live Dynamic Redirection Tracking: Because PhishGuard AI never contacts destination servers, complex server-side HTTP 302 Cloaking and geofenced redirects cannot be tracked.
  • Zero Domain Ownership Verification: The platform does not query active WHOIS databases or TLS certificate authorities to avoid outbound telemetry footprints.
  • Evasion via URL Shortener Chaining: Multiple chained URL shorteners require recursive resolution which requires network connectivity.
Future Enhancements
  • Browser Extension Integration: Compile a lightweight WebExtension (Chrome/Firefox) integrating PhishGuard AI's feature pipeline to warn users in real time.
  • Deep Learning Sequential Models: Train Character-level Bi-directional LSTM or Transformer (BERT-style) sequence encoders on URL strings.
  • Passive DNS & Certificate Transparency Logs: Ingest offline TLS certificate transparency feeds for zero-day domain entropy scoring without visiting hosts.
